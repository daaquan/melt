## Problem Statement

Phase 1 stores an immutable source and a stub digest. Search only hits words that already appear in the clipboard (or the stub). The reason you saved the item lives in your head, or in a paper log the assignment asked for, not in melt.

Phase 2 adds that reason as a one-line **useful for** you write later, in the inbox. Capture stays a hotkey.

## What Makes This Cool

You copy, press the hotkey, file nothing. Later you type `sqlite wal for billing`. The list still shows the source title. Under it, your line. Search with *your* words and the original sits beside a digest still labeled derived.

The whoa is not tags. It is finding yesterday's clip without remembering the source wording.

## Constraints

- Phase 1 contract stays: one FastAPI process, SQLite, host helper, localhost. No worker, snapshots, or LLM in this tree.
- `sources.hash` / `normalized_body` never UPDATE. Digests stay derived. User text is neither.
- Hotkey and `POST /v1/captures` unchanged. Zero extra keystrokes at copy time.
- English source of truth. New strings in `locales/en.json`; `ja.json` may copy English.
- Inbox stays the locked two-column layout. No third "You" column this tree.
- Public OSS, Apache-2.0, CI is the second reviewer.

## Premises

1. Phase 2 is an after-the-fact one-liner on an existing source. Not a capture prompt, not tags/projects, not LLM digest.
2. The line is the user's voice. It does **not** go in `digests.useful_for_json` (stub `[]` stays for later model output).
3. Capture path unchanged.
4. The line is FTS-indexed. Empty is valid. Phase 1 inbox still works with no lines written.

## Approaches Considered

- **A — One-row table + detail form only.** Ruled out as the ship: the field would hide in the detail pane and fail the "find at the moment of work" test.
- **B — Versioned contexts (append-only like digests).** Ruled out this tree: a five-word memo does not need history yet. Upgrade path exists (same table can grow a version column later).
- **C — A's schema, visible on the list, key `n` (chosen).** Same table as A. List keeps the source title. Non-empty context shows as list meta. `n` focuses the field when focus is not already in an input.

## Recommended Approach

Approach C.

### Data

New table. Not a column on `sources` (identity stays immutable). Not a digest row.

```text
contexts
  source_id  TEXT PK  REFERENCES sources(id) ON DELETE CASCADE
  body       TEXT NOT NULL
  updated_at INTEGER NOT NULL
```

Normalize, in this order: Unicode NFC → replace `\r\n` / `\r` / `\n` with a single space → trim → count `len(body)` as Unicode code points (`len` of the Python str). Max **200**. After normalize, empty → **DELETE** the `contexts` row (list meta gone, FTS `user_text` `''`). Over the cap: JSON `POST /context` → `400` `too_long`; form → no write, 303 with `context_error=too_long`. After normalize, if `looks_like_secret(body)` and not `MELT_ALLOW_SECRETS`: JSON `400` `secret_blocked`; form → no write, 303 `context_error=secret_blocked`. Same patterns as ingest.

- Recapture of the same source does **not** clear context and does **not** rewrite the FTS row.
- Last capture undo that deletes the source also deletes context (FK CASCADE). FTS row for that `source_id` is deleted in the same txn as today.

### FTS

Today `sources_fts` is `(source_id UNINDEXED, body, digest_text)` and ingest writes `digest_text = " ".join([summary, *phrases])`.

`init_db` today is `CREATE IF NOT EXISTS`, so an existing 3-col `sources_fts` will **not** grow a column. `user_version = 0` is true for both a new file and a Phase 1 file. Do **not** treat “no `contexts` table” as “fresh.”

Migrate (startup, before serving). Parse **before** DROP:

1. If `PRAGMA user_version >= 1`, return.
2. Load every source + latest digest. `json.loads(retrieval_phrases_json)` must succeed for all rows. On failure: do **not** DROP; raise; leave `user_version = 0`.
3. One `BEGIN IMMEDIATE`: `CREATE TABLE IF NOT EXISTS contexts`; `DROP TABLE IF EXISTS sources_fts`; `CREATE VIRTUAL TABLE sources_fts USING fts5(source_id UNINDEXED, body, digest_text, user_text)`; INSERT rebuilt rows (`digest_text` = ingest helper, `user_text` from `contexts.body` or `''`); `PRAGMA user_version = 1`; COMMIT.

A crash rolls back to the 3-col table. Never `CREATE IF NOT EXISTS` the 3-col FTS first, then bump the version. SCHEMA for new files is 4-col FTS + `contexts`; the same migrate still runs (zero source rows).

`_INGEST_LOCK` is `threading.Lock()`, not RLock. **Only `delete_capture` acquires it** among delete/undo. `undo_latest` must not `with` the lock then call `delete_capture` (deadlock). Undo: inside `delete_capture`'s lock (or a shared helper that already holds it), SELECT latest capture id, then delete. Ingest and context upsert also use this lock + `BEGIN IMMEDIATE`.

Context FTS upsert, same txn as the `contexts` write, rebuild from **sources + latest digest + new user_text** (never copy the old FTS row):

1. `DELETE FROM sources_fts WHERE source_id = ?`
2. `INSERT` four columns: `normalized_body`, `digest_text_for(source_id)`, `user_text` = stored body or `''`.

First ingest: `user_text = ''`. Recapture: no FTS write.

Quoted MATCH stays (`fts_query`). Empty `q` on `GET /v1/search` stays 200 + empty hits. Homepage recency unchanged.

### Reads that the inbox uses

`recency_list`, `search_sources`, and `source_detail` each `LEFT JOIN contexts` (or select `contexts.body AS context_body`). The HTML list/detail does not call GET JSON.

### HTTP

Same auth as inbox (cookie or Bearer). Cookie POSTs stay `SameSite=Strict` as today. There are **no CSRF tokens**; do not add them.

| Method | Path | Role |
|---|---|---|
| POST | `/v1/sources/{id}/context` | JSON `{ "body": "..." }` → 204. Missing source → 404. `too_long` / `secret_blocked` → 400. |
| POST | `/v1/sources/{id}/context-form` | Form `body` plus hidden `q`. Save button; Enter submits. 404 → 303 `/`. `too_long` / `secret_blocked` → no write, 303 `/?selected={id}&context_error=...` (keep `q` only if it would still MATCH after this write). Success: 303 `/?selected={id}` plus `q` **only if** the saved body still matches that `q`; if the line was cleared or changed so `q` misses, omit `q` (recency + selected). Do not copy `reuse-form` (302, drops `q`). |
| GET | `/v1/sources/{id}` | Add `context: string \| null` (stored body, or `null` if no row). |

No change to capture, undo, delete, reuse kinds.

### Inbox UI (delta on the Phase 1 wireframe)

```text
[search]
[list]
  source first line (unchanged)
  meta: occ badge | useful-for line if present
[detail]
  Source (primary)          Digest stub (secondary)
    <form useful for>         (unchanged; no Useful for heading)
    input one line + Save (Enter submits; no textarea newline)
  actions: Copy | Mark used | Delete
```

- Heading `context.heading` (`Useful for`), placeholder `context.placeholder`, button `context.save`. Not inside the digest pane.
- Empty: placeholder, no fake "pending".
- Keyboard in `inbox.js`: ignore shortcuts when the active element is `INPUT` or `TEXTAREA`, or when `isComposing`. `n` focuses `#context-body`. **Autofocus search only when `selected` is absent.** A selected detail page does not steal `n` into `#q`. `c` must not copy-source while typing in the context field.
- `context_error` query: show `error.too_long` / `error.secret_blocked` (existing keys) above the context field.
- List title stays source preview (Phase 1 autoplan decision 8). Context is extra meta, 80 chars, not a replacement title.
- XSS: Jinja autoescape. Body is text, not markdown.

### Tests

pytest, first tree:

1. POST context → GET `context` is the string; FTS on those words returns `source_id`.
2. Empty/whitespace POST deletes the row; search on old words misses.
3. JSON: over 200 code points → 400; 200 exactly → 204. Form: over 200 → 303 `context_error=too_long`, row unchanged.
4. Recapture: context row count unchanged, body unchanged; FTS still hits source words after a later context upsert.
5. Delete last capture / undo that drops the source: no orphan `contexts` row, FTS row gone.
6. Inbox HTML: context in list meta and source pane; digest pane has no user body. XSS escaped.
7. Capture helper and `POST /v1/captures` tests still pass with no new headers.
8. POST context leaves `digests.useful_for_json = []`; GET `context` is the user line, not under `digest`.
9. Open a Phase 1 file (`user_version = 0`, 3-col FTS, no `contexts`): `init_db` → `user_version = 1`, 4-col FTS, old source MATCH still hits. If phrases JSON is garbage, migrate raises and `user_version` stays 0, FTS still 3-col.
10. Success 303 keeps `q` when the saved line still MATCHES; clearing the line that was the only hit omits `q` and still shows that source on recency.
11. `looks_like_secret` on context: 400 JSON / form 303 `secret_blocked`; `MELT_ALLOW_SECRETS=1` stores.
12. Replace A→B: search A misses, B hits once, one FTS row.
13. `undo_latest` under load with ingest: no deadlock; deletes the capture that was latest at lock time.

### Stack

Unchanged: Python 3.12, FastAPI, SQLite FTS5, server-rendered HTML.

## Open Questions

- CJK: FTS5 unicode61 tokenizes whitespace-free Japanese as one token. Substring search will miss. Same as Phase 1 source text. Do not block this tree on a tokenizer rewrite.
- 200 code points vs a hard 5-word cap. 200 is the closed default (a short sentence, not an essay).

## Success Criteria

Not "people tag things."

- You write useful-for on **10 real items** already in the inbox (not a fixture dump).
- Using the **full stored line** as `q` (space-separated tokens FTS already understands; ASCII phrases this tree), the intended item is in the **top 3**. Do not treat Japanese substring search as an acceptance test.
- Capture still works with the same hotkey; a session of 10 captures does not require opening the inbox.
- Test 8 fails a PR that stores the line in `digests.useful_for_json`.

## Failure modes

| Path | Failure | Test | User sees |
|---|---|---|---|
| Migrate | Bad phrases JSON | 9 | Startup error; old FTS kept |
| Migrate | Kill after DROP | 9 (txn) | Old 3-col on restart |
| Undo+ingest | Deadlock / wrong row | 13 | Undo works; latest at lock time |
| Form too_long | Silent 303 | 3 | `context_error=too_long` |
| Form secret | Bypass ingest deny | 11 | `secret_blocked` |
| Save + q | Ghost selected | 10 | Recency + that source |
| FTS upsert | Delete without insert | 4, 12 | Source words still MATCH |
| XSS | Raw context in HTML | 6 | Escaped text |

No silent critical gap after D3/D8/D10.

Sequential implementation, no parallelization opportunity. `db.py` is the hub.
