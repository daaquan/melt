## Problem Statement

Passing information (copied text, URLs) dies in the clipboard or in a notes dump. Readwise/Matter already own “capture highlights, resurface later.” melt is not a reader and not a chat-over-vault. It is a near-zero-friction capture loop that stores **immutable source**, a **reproducible digest**, and later **find + reuse**.

First user: the builder (daily clipboard). Public GitHub OSS from day one. English is the source of truth; UI strings live in locale files.

## What Makes This Cool

Copy anything, press a hotkey, never file it. Later, search with words that appear in the source (or in a stub digest’s retrieval phrases) and see the original beside a digest labeled derived. Recapturing the same thing counts (`captured 3 times`); it is evidence, not duplicate noise. The whoa is finding yesterday’s snippet and marking it used.

## Constraints

- Greenfield repo. Host: Linux. **Host publish** `127.0.0.1:8080:8080` (not on the LAN). Inside the container, Uvicorn listens on `0.0.0.0:8080`. Do not bind Uvicorn to container `127.0.0.1`. Token = full access.
- Public OSS; English code/docs/UI source strings; extra locales later.
- No reader, FSRS, chat, knowledge graph, embeddings, mobile, or team features in Phase 1.
- Capture client stays thin. Knowledge processing stays on the server.
- Do not fork or copy Karakeep (AGPL-3.0 + bookmark ontology). Documentation may be read as a reference.
- Review gates ride with the first working loop: LICENSE, README, provenance tests, CI. Not an empty-repo prelude. Not CODE_OF_CONDUCT / Conventional Commits / strict i18n lint until an external contributor appears.
- Clipboard: `text/plain` only. Images, HTML-only, and empty clipboard are `Failed`.
- Payload cap: 1 MiB UTF-8. Oversize is `Failed` (4xx), not truncated.
- URL snapshots exist so digest/search can use fetched text. Inbox **Source** column is always the submitted payload (canonical URL or text). Fetched bytes are labeled **Fetched copy**, never “Source.”

## Premises

1. Phase 1 validates Capture → Digest → Save → Find → Reuse via hotkey. No reader/FSRS/chat/graph.
2. Steal Readwise’s habit only. Clipboard text or URL. Source immutable. Digest is derivative.
3. GitHub public. English source of truth. UI strings in `locales/en.json`. No App Store.
4. Distribution: GitHub + Docker Compose (**one API** on localhost) + a **host** hotkey helper. Worker/snapshots are a later PR.
5. LICENSE, CI, and provenance/dedup tests ship the same week as the loop.
6. Status quo is Readwise-like tools or a notes dump. Unique gap: capture-without-filing plus AI not overwriting source.
7. Dedup merges identical **sources** and keeps every **capture** occurrence.

## Approaches Considered

- **A — Single-process dogfood:** one FastAPI+SQLite process. Ruled out: a second capture client (CLI/browser) would force an ingest rewrite. (Occurrence history is a schema choice, not a process-count choice.)
- **B — Ingest core + Tauri tray:** ruled out for Phase 1 because Linux global hotkeys in Tauri delay the Saved toast. Revisit after the loop is a habit.
- **C — Dumb capture + provenance server (chosen):** OS shortcut + host helper; server owns sources/captures/digests/jobs/reuse; Compose; CI enforces provenance.

## Recommended Approach

Approach C.

### Runtime shape

```text
OS global shortcut (host)
    → melt-capture (host CLI)
        → POST http://127.0.0.1:<port>/v1/captures
            → API persists source + capture + stub digest in one txn, returns 201
                → worker (snapshots, digest)
                    → SQLite WAL
                        → inbox at http://127.0.0.1:<port>/
```

Compose publishes **one API service**. The helper never runs in the container.

### Capture helper (host)

- Language: Python 3.12 script in-repo (`scripts/melt-capture`).
- Env: `MELT_API_URL` (default `http://127.0.0.1:8080`), `MELT_TOKEN` (Compose and helper share the same value; generate with `openssl rand -hex 32`).
- Clipboard: pick **one** backend. If `WAYLAND_DISPLAY` is set, only `wl-paste --type text/plain`. Else only `xclip -selection clipboard -t text/plain -o`. Do not mix Wayland and X11. Empty, missing `text/plain`, or image → toast `Failed`, no POST.
- Notify via `notify-send` using keys from repo `locales/en.json` (same catalog as the inbox). Resolve path: `MELT_LOCALE_DIR` if set, else directory `locales/` relative to the repo root (walk up from the script). Missing key → show the key name and treat as `Failed`. Do not hardcode user-facing English in the helper.
- No window during capture.
- Failed POST (network, 5xx, 401/403, timeout): append one JSON line `{ "ts", "kind", "body", "idempotency_key", "error" }` to `~/.local/state/melt/failed.jsonl` (file mode **0600**) and toast `Failed`. Before any POST: trim; skip and dead-letter (move to `failed.dead.jsonl`) if empty or > 1 MiB — do not hit the API. On the next run: collapse only lines that share the same `idempotency_key` (do **not** collapse same body / different keys). Replay from the top. Drop a line only after **HTTP 2xx** (including `201`). On **400/413**, dead-letter that line and **continue** the rest. On 401/403/5xx/network, stop replay and leave remaining lines (do not re-append). Then POST the current clipboard. Replay 2xx toasts the same as a live capture. Helper must not run two processes against the file at once (lock or single-instance).
- Helper may call `POST /v1/captures/undo` (optional second shortcut, e.g. Ctrl+Alt+Shift+M) immediately after a mistaken capture. Inbox has Delete on the detail pane.
- README documents GNOME Settings → Keyboard → Custom: command `melt-capture` plus a sxhkd snippet. KDE is the same idea. Document `MELT_LOCALE_DIR` and an install path so shortcuts do not depend on cwd.

### HTTP: ingest

`POST /v1/captures`  
Header: `Authorization: Bearer <token>`  
Also: `Idempotency-Key: <uuid>` (required). Helper generates one UUID **per hotkey press**, stores it on the failed.jsonl line, and reuses it on replay. Same key → same `capture_id` (no extra occurrence). New hotkey press → new key even if body matches.  
Body:

```json
{ "kind": "url" | "text", "body": "..." }
```

- `kind` is required. The helper sets `url` if the trimmed clipboard matches `^https?://` (no whitespace), else `text`.
- Empty `body` after normalize → `400`.
- Over 1 MiB → `413`.
- Success → **`201`** (scope amendment: stub digest is written in this transaction)

```json
{
  "capture_id": "...",
  "source_id": "...",
  "occurrence_count": 3,
  "digest_status": "stub"
}
```

`occurrence_count == 1` → toast `Saved`. `> 1` → toast `Saved · nth time`. Recapture (UNIQUE hit) still returns **201** with a new `capture_id` and `digest_status` of the existing latest digest (`stub` or later `llm`). Do not insert a second stub on recapture.

### Normalize + source identity

Source identity is **SHA-256 of the submitted normalized payload**, never of a fetched page.

- **text:** Unicode NFC, trim leading/trailing whitespace, keep inner newlines.
- **url:** parse as URL; lowercase host; **keep fragment**; drop tracking query keys `utm_*`, `fbclid`, `gclid`; sort remaining query keys; drop default ports; drop trailing slash on path `/` only (keep path otherwise); scheme `http` and `https` are **not** collapsed (different sources). Identity string is `url\n` + canonical URL.

Fetched page bytes belong in `snapshots`, not in `sources`. A later successful fetch does **not** update the source row.

### HTTP: inbox (same origin, same token)

Browser: unauthenticated `GET /` renders a login form only (not the inbox). `POST /v1/login` with form field `token`. On match with `MELT_TOKEN`, set cookie `melt_token` = that value, flags `HttpOnly; SameSite=Lax; Path=/` — **do not set Secure** (HTTP on 127.0.0.1). Inbox routes require that cookie or `Authorization: Bearer`. Host access is `http://127.0.0.1:8080` via Compose publish (see Constraints).

| Method | Path | Role |
|---|---|---|
| GET | `/` | No cookie: login form. Cookie: inbox (locked wireframe) |
| GET | `/v1/search?q=` | FTS results + provenance |
| GET | `/v1/sources/{id}` | Source `raw_body` + latest digest + capture times |
| POST | `/v1/sources/{id}/reuse` | `{ "kind": "copy_source" \| "mark_used" }` |
| POST | `/v1/captures/undo` | Delete **latest** capture for this user (single-user). If that was the last capture of a source, delete the source + stub digest too. |
| DELETE | `/v1/captures/{id}` | Delete one capture; same cascade if last. |

No search-event logging.

### Data model

| Table | Rule |
|---|---|
| `sources` | Canonical identity only. Columns: `id`, `kind`, `normalized_body`, `hash` **UNIQUE**, `created_at`. Never UPDATE body/hash. Used for dedup, not as the clipboard photograph. |
| `captures` | `id`, `source_id`, `captured_at`, `idempotency_key` **UNIQUE**, `raw_body` (exact clipboard text as submitted, before normalize). One row per hotkey press. Inbox **Source** column shows `raw_body` of the selected capture (or latest). |
| `digests` | Versioned derivatives. First tree: one stub row on source INSERT. `source_id`, `summary`, `useful_for_json`, `retrieval_phrases_json`, `model=stub`, `prompt_id=stub-v1`, `source_hash`, `created_at`. Never in-place replace. |
| `snapshots` | **Deferred.** Do not create in the first mergeable tree. |
| `processing_jobs` | **Deferred.** First tree writes stub digest in the ingest transaction. |
| `reuse_events` | `copy_source` or `mark_used` only. |

Hash collision on insert: compare `kind` + `normalized_body`. If they match, attach a new capture (or return existing capture when `Idempotency-Key` matches). If they differ, **fail the request** (do not silently merge).

### SQLite

One file on a Compose volume. `PRAGMA journal_mode=WAL; busy_timeout=5000`. Single API process is the only writer. No worker in the first tree.

### Digest (first tree)

In the ingest transaction, after source insert (or UNIQUE hit): if this source has no digest yet, insert stub: `summary` = first 240 chars of digest input (`raw_body` for text, canonical URL for url kind); `retrieval_phrases` = tokens ≥ 4 chars (cap 50); `useful_for` = `[]`; `model` = `stub`. Recapture does not insert another stub.

URL fetch / LLM digest: **not in this tree** (see NOT in scope).

### Search and list title

FTS5 indexes `sources.normalized_body`, latest snapshot `extracted_text` if any, plus the **latest** digest’s `summary`, `useful_for`, `retrieval_phrases`.

List title: latest digest `summary` truncated to 80 chars; else first line of text body; else canonical URL.

Phase 1 success is **lexical** FTS, not semantic search.

### Inbox UI

Locked wireframe: [inbox-wireframe.html](./inbox-wireframe.html)

### Tests that define the product

pytest. First tree only (no snapshot/LLM tests):

1. Same normalized text → one `source`, two `captures`.
2. URLs that differ only by trailing slash on `/` or `utm_*` → one source. **Fragments are significant** (different sources).
3. Ingest is one transaction: `201`, exactly one stub digest on first create, `sources.normalized_body`/`hash` unchanged after.
4. Recapture: `captures` +1, digest row count unchanged.
5. Concurrent two POSTs of the same payload → one source, two captures (UNIQUE path).
6. Search hits include `source_id` and capture timestamps.
7. Inbox templates and the helper resolve `Saved` / `Saved · nth time` / `Failed` / empty-state from `locales/en.json`. `Already seen` is not a key.
8. Helper dead-letter: 400/413 skip that line and continue; do not block the file.

Worker/snapshot/LLM tests are **not** in this CI. Add them in the PR that implements fetch.
